# Contributing

[Back to the directory](README.md)

Open a pull request for a new entry or a correction. If the change needs discussion first, open an issue with the entry name, the specific claim, and the source you checked.

## What belongs in the directory

Each resource should help with a defined defensive task. An assistant, data source, framework, standard, or evaluation can qualify if the linked material shows how it fits. Link to an official project page or the documentation for the feature you describe. Disclose your affiliation if you work on the resource.

Use the closest existing section and follow its resource, kind, and use columns. Describe the task in one or two sentences. State when an assistant requires a managed service or runs on the team's own infrastructure if the primary source specifies it. For anything that takes action, identify the documented review or approval point. If you evaluated the resource yourself, describe the inputs, version, and limits of that evaluation in the pull request.

For a claim about a fix, cite a vendor or assigning authority and specify the applicable version or branch. For an evaluation claim, cite the dataset and the population it covers. A vendor's results on its own queue apply to that queue.

## Corrections and removal

When a tool moves, goes unmaintained, or changes its permissions, update the description or propose removing the entry. Include a dated primary source and explain what a team relying on the old entry needs to know. A reachable link is one check. The page must also support the claim it accompanies.

Use synthetic or public, authorized examples in contributions. Keep real credentials, internal logs, and organization-specific asset details out of issues and pull requests.
